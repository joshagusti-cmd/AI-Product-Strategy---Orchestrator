# The Prototype Bet

## What I Built
A clickable, multi-page governance platform prototype for the Aiven Agent Orchestrator, covering the surface a real buyer would expect from an "agent governance platform," not just the original single-screen demo. See [`prototype/USER_GUIDE.md`](prototype/USER_GUIDE.md) for how to actually use it — kept current alongside every feature below, not written once and left behind:

- **Command Center** (`index.html`) — an executive enters a business objective, the orchestrator decomposes it into a task graph, assigns it across six specialized agents running on different models, pauses execution for human approval on a flagged risk, then produces a governed executive action plan with a full per-agent audit trail. The current objective, scope, and model routing can be saved as a named template and reloaded later ("run this same analysis monthly").
- **Agent Registry** (`agents.html`) — every agent the orchestrator governs, across departments, with tier (Leader/Filler/Killer/Core), assigned model, status, and what it can/can't do without a human. Filterable by tier and, now, by real department — the "Departments covered" KPI tile is clickable and jumps straight to the filter (closes the "per-department drill-down" backlog item, for this page). The registry is now the pipeline's real source of truth, too: a new **Pipeline** column shows each real Command Center agent's step number and Writer/Risk-gate role, and an Admin-only **Enabled** toggle genuinely removes an agent from the very next real Orchestrate run.
- **Policy Editor** (`policies.html`) — the compliance-owner control surface: autonomy level, escalation risk threshold, and escalation rule per tier, editable instead of hardcoded (closes the "Policy editor for compliance owners" backlog item at prototype fidelity) — and, now that RBAC is real, actually restricted to the Admin/Compliance Owner roles rather than just labeled that way. The Core-tier policy card is marked "Enforced on real Orchestrate runs" because it now really is: it's the one policy the Command Center's real orchestration pipeline actually checks.
- **Approval Queue** (`approvals.html`) — the org-wide backlog of agent actions waiting on a human decision, filterable by risk and, now, by real department. A real phone-first companion (`mobile-approvals.html`, linked from this page) scopes the same live queue to just pending/high-risk cards and big Approve/Reject buttons, for reviewing on the go.
- **Audit Trail** (`audit.html`) — a searchable, exportable (JSON/CSV) real-time log of every agent and human action, matching the audit cadence in the Governance Policy. Now also has an **"Ask the audit trail" panel** — a real Claude call, grounded strictly in this workspace's own real log entries, that answers a natural-language question or says plainly when the log doesn't support one.
- **Workflow History** (`workflow-history.html`) — a real, searchable archive of every completed Orchestrate run's full deliverable (executive summary, findings, recommendations, risk flags, every agent step), not just the Audit Trail's one-line pointer to it — still there after you've navigated away, closing the "workflow history / versioned deliverable archive" backlog item. Filterable by real department too, since a run's actual department scope is part of what's archived. Check any two runs and click "Compare selected" for a real side-by-side view of both full deliverables.
- **Model Spend Dashboard** (`spend.html`) — cost by tier and by model provider, tied to the cascading Leader/Filler/Killer pricing model in `03-the-margin/cost-curve.md`; the provider breakdown is live off the Agent Registry's current model assignments. Now also shows **real, measured Orchestrate spend** — every real Claude call your workspace has made, priced at real Anthropic per-model rates, broken out by model and by agent — not modeled numbers.
- **Shadow AI Audit** (`shadow-ai.html`) — the illustrative shadow-tool findings from `05-the-guardrails/compounding-system.md` as a historical backdrop, plus a "Run Shadow AI Scan" action that now does a **real discovery scan** of this workspace's own real data (Agent Registry drift + real Orchestrate substitution telemetry — see below) and routes any new finding to a govern/kill decision.

All seven governance pages read and write a **real Postgres database on Supabase** (`assets/data.js` talks to it directly via `supabase-js`, no build step), with **real multi-tenant auth**: anonymous visitors get a read-only view of a shared public demo, and signing in (email magic link, no password) auto-provisions your own private, isolated workspace — approving something, saving a policy, or deciding a Shadow AI finding shows up immediately across pages, scoped to whichever workspace you're in. The Command Center's "Orchestrate" button calls a real Claude model through a Supabase Edge Function instead of a scripted timeline, gated to signed-in users since it's a real, metered API call — see "Horizon 1 → 2: real backend, real model calls, real auth" below.

## Tool Used
Claude Code (Claude Sonnet 5) — hand-built HTML/CSS/JS, no framework, plus a Supabase Postgres database and Deno Edge Function for the backend (see `supabase/README.md`). Runs standalone in any browser, and deploys to GitHub Pages via `.github/workflows/deploy-pages.yml` (see the repo README for the live URL once Pages is enabled).

## AI Value Archetype
Orchestrator — consistent with the Module 1 diagnostic. It doesn't compete with Claude or GPT on raw model capability; it coordinates and governs them.

## Horizon 1 → 2: real backend, real model calls, real auth
The lead items across Horizon 1 and the start of Horizon 2 in `06-the-pitch/roadmap.md` are now built, at design-partner-demo fidelity:

- **Persistent backend** — a real Supabase Postgres database (`supabase/migrations/`) with five tables (agents, policies, approvals, shadow tools, audit log), replacing the localStorage simulation.
- **Real, independent multi-agent orchestration** — the Command Center's orchestration run is six real, independent Claude API calls through a Supabase Edge Function (`supabase/functions/orchestrate/`), one per agent, run in the same Research → Finance → Ops → Risk & Compliance → Strategy → Executive Writer order the UI narrates, each agent seeing the prior agents' actual output as context. The Risk & Compliance step runs on Claude Opus 4.8 (the highest-stakes step gets the most capable model); everything else runs on Claude Sonnet 5. The Writer's call also synthesizes the run's executive summary, findings, recommendations, and risk flags from what the other five actually found — not scripted copy, and not one call inventing all six steps at once.
- **Real multi-tenant auth** — email magic-link sign-in (no passwords), with a public read-only demo workspace and a private, isolated, auto-provisioned workspace per signed-in user. Orchestrating (a real, metered API call) requires signing in — the Edge Function itself rejects anonymous requests, so a random visitor can't run up the API bill.
- **Real spend cap, tied to a real plan tier** — every workspace has a `plan` (Free/Pro/Enterprise → 20/100/500 Orchestrate runs per rolling 24h), enforced server-side in the Edge Function itself via the service role key, not just something the client checks. The Command Center shows a live "X/Y runs used today" count once signed in, and an admin can change the plan from the Workspace modal — no real billing/payment processing, "upgrading" just changes the enforced cap immediately.
- **Real teams/invites** — a workspace member can invite a teammate by email (the "Workspace" button in the auth widget); they join that workspace automatically the next time they sign in with that email, and a user who belongs to more than one workspace gets a switcher to pick which one is active. Not built yet: leaving a workspace, or changing your own role.
- **Real RBAC within a workspace** — three roles (Admin, Compliance Owner, Analyst) enforced at the RLS layer, not just the UI: Admin gates agent model reassignment and team management, Admin-or-Compliance-Owner gates policy edits and Shadow AI govern/kill decisions, and everything else (approving, running a Shadow AI scan, orchestrating) stays open to any member. Buttons and inputs a signed-in user's role doesn't cover are disabled in the UI, and the underlying database call would be rejected either way.
- **Real automatic model routing** — the Command Center's "Auto-route models by risk/complexity" toggle (on by default) hands model selection to the Edge Function itself: a real, deterministic three-tier cascade — cheap models for routine, low-stakes objectives, escalating to Claude Opus 4.8 on the higher-stakes steps when the objective's text matches governance/compliance/financial risk keywords or its department/data-source scope is large — mirroring the Leader/Filler/Killer cascade this product's own pricing model is built around (`03-the-margin/cost-curve.md`). The post-run toast names exactly which tier was picked and why. Turning the toggle off falls back to the manual per-agent dropdowns.
- **Real, measured spend telemetry** — every one of the six real Claude calls in an Orchestrate run logs its real model and real token counts server-side (`orchestrate_call_log`, via the service role key so a client can't fake it), even for calls from a run that later fails, since those tokens were still really billed. The Model Spend Dashboard's new "Real Orchestrate spend" panel prices that log at real, hardcoded per-model Anthropic rates and breaks it down by model and by agent — replacing the modeled cost-curve numbers with what your workspace has actually spent.
- **The Policy Editor now really gates the Orchestrate pipeline** — every Command Center agent is Core tier, so the workspace's Core-tier policy is the one the Edge Function checks: with Autonomy set to "Approval-required" or "Two-gate," a real run whose Risk & Compliance Agent flag scores at or above that policy's risk threshold pauses for real, before the Strategy and Writer calls (and their real API cost) ever run. The run's already-completed steps and full context are held server-side against a real `approvals` row; approving it (from the Command Center's own panel or the org-wide Approval Queue) genuinely resumes the remaining Claude calls and produces the deliverable, and rejecting it genuinely ends the run — no fabricated result either way. "Autonomous"/"Advisory" never pause it, matching what those labels say. A true second gate (separate approval to *distribute* the finished deliverable) isn't modeled, since the Command Center has no separate "send externally" action to gate.
- **The Shadow AI Audit's scan is now a real discovery, not a fixed fictional list** — "Run Shadow AI Scan" reads two real signals from this workspace's own data: which of the six real Command Center agents' Agent Registry entries declare a model this backend can't actually call (real registry drift, straight from the `agents` table), and which real Orchestrate runs actually requested an ungoverned model and got silently substituted (real telemetry from `orchestrate_call_log.requested_model`, migrations/0012). Every finding is triaged exactly like before — govern or kill — but now derived from what's really happened in this workspace, not three hardcoded illustrative rows revealed one click at a time.
- **Every completed run is now archived in full, not just narrated in the moment** — `orchestrate_runs` (migrations/0013) stores the whole deliverable (executive summary, findings, recommendations, risk flags, every agent step) for both a fresh run and a paused run resumed to completion. `workflow-history.html` is a real, searchable browse-and-open archive of it — the Audit Trail still logs the one-line "drafted the executive action plan for…" pointer, but this is the deliverable itself, persisted.
- **The Audit Trail answers real questions now, grounded in its own real log** — a new `audit-qa` Edge Function takes a question, pulls this workspace's most recent real `audit_log` rows (up to 300), and asks Claude to answer strictly from them — citing the specific entries it drew from, and saying so plainly when the log doesn't support an answer rather than inventing an actor, action, or timestamp. Gated to signed-in users and rate-limited per workspace (40 questions/rolling-24h, its own cap — `audit_qa_log`, migrations/0014 — separate from Orchestrate's plan-tied cap, since this is a different, much cheaper real Claude usage surface). Every question and answer is persisted too, so a past answer is still there after you navigate away.
- **Saved objective templates are real, client-writable rows** (`objective_templates`, migrations/0015) — no Edge Function or Claude call involved, just the same real Postgres + RLS pattern as policies/approvals. Saving a template captures the objective, department/source scope, auto-route setting, and every per-agent model assignment; loading one drops all of it straight back into the Command Center's form, ready to run.
- **Per-department drill-down is a real filter, not a mockup** — Agent Registry, Approval Queue, and Workflow History each build their department chip list from whatever departments actually exist in that page's own real data (no fixed list to keep in sync), and filtering is a real predicate over real rows. No database change was needed — `agents.dept`, `approvals.dept`, and `orchestrate_runs.departments` already existed.
- **Mobile companion approvals view is a real, purpose-built phone page, not a squeezed desktop table** — `mobile-approvals.html` is capped at a phone-shaped width even on a wide viewport, reads a new lean query (`Aiven.getApprovalQueue()` — just the `approvals` table, not the full five-table `loadState()` the desktop pages pull) and writes through the exact same `decideApproval()`/`resumeOrchestrate()` calls as the full Approval Queue, so approving from a phone has the identical real effect — including resuming a paused Orchestrate run — as approving from the desktop console. It's deliberately not a tenth entry in the byte-identical 8-page subnav; it's linked from `approvals.html` and links back.
- **Workflow History now compares two real runs side by side, closing that half of the backlog item** — check any two rows in the archive and click "Compare selected" for a two-column view of both full deliverables (objective, scope, model, executive summary, findings, recommendations, risk flags, every agent step), reusing the same detail-rendering the single-run view already had. It's a real juxtaposition of two real archived runs — not a computed text diff highlighting what changed, and no database or Edge Function change was needed since it's built entirely from data the page already loads.
- **Any agent, from anywhere, connects for real — not just Claude ones Aiven runs itself.** The Agent Registry's new **+ Add external agent** flow issues a real API key + endpoint (`supabase/functions/agent-events/`, `supabase/migrations/0017_external_agent_connector.sql`) for any agent a workspace already runs elsewhere — any stack, any language. That agent's own code reports real activity in, landing in the same registry, Audit Trail, and Approval Queue an internal agent uses; a reported risk flag is judged by the identical Core-tier policy the internal pipeline uses, and the external agent's own code can poll a real `check_approval` action before proceeding on something gated. Only a SHA-256 hash of the key is ever stored server-side — the raw key is shown exactly once, at registration or regeneration. The one honest limit: Aiven can't force an external agent's code to call in or honor the answer, since it never executes that agent itself — no governance platform can do more than that for something it doesn't run.
- **The Orchestrate pipeline is now data-driven, not a hardcoded six-agent array** — the Edge Function reads whichever `agents` rows in the workspace's own Agent Registry are marked `sequence_order`/`enabled` (`supabase/migrations/0016_data_driven_pipeline_agents.sql`), in that order, with exactly one flagged `is_writer` and one `is_risk_gate` — validated at load time so a bad manual edit fails a run loudly and safely rather than silently misgoverning it. Model routing generalized from fixed per-id defaults to a pipeline *slot* (gather/gate/synth/writer), so auto-route still works whatever the registry's real shape is. This also surfaced and fixed a real pre-existing gap: the live pipeline's Risk & Compliance Agent had never actually had a registry row — the seeded "Compliance / Audit Agent" is a different, illustrative Fraud-Ops agent from the original case study, untouched. Agent Registry's new Enabled toggle is the first real admin lever over this — reordering the pipeline and editing an agent's prompt-role text from the UI are still open, held back deliberately for this pass.

Full detail — schema, the auth/multi-tenancy model, what's still simplified about it, and the two manual steps (the `ANTHROPIC_API_KEY` secret + the auth redirect URL allowlist) — is in `supabase/README.md`.

## What's still simulated
Being direct about the remaining gap to "fully functional SaaS," per the Horizon 1/2 roadmap:
- **Teams and RBAC are real, but the three roles are fixed bundles** — a workspace member can invite a teammate by email with a chosen role (Admin/Compliance Owner/Analyst), and they join automatically; an admin can change any other member's role or remove them. What's still open: no custom roles or fine-grained permissions beyond those three bundles, and no self-service "leave workspace" or self role-change. See `supabase/README.md` for the exact gaps.
- **No real integrations** — NetSuite/Salesforce/Zendesk/Snowflake/Workday are chips in the UI, not live connections.
- **Reliability figures are still modeled**, not measured — transcribed from `04-the-contract/golden-dataset.md`, not live telemetry. Real Orchestrate spend is now measured (see above); the Model Spend Dashboard's Leader/Filler/Killer tier breakdown stays modeled, since it's the fraud/dispute vertical's economics from `03-the-margin/cost-curve.md`, not something this prototype's Command Center demo runs actually represent.
- **Model routing (manual and automatic) is real but Claude-only** — reassigning an agent's model in the Command Center, or letting Auto-route pick it, actually changes which model runs that agent's real call (see `resolveAgentModel` / `computeAutoRoute` in `supabase/functions/orchestrate/index.ts`), not just a cosmetic label. Only "Claude Sonnet 5", "Claude Opus 4.8", and (in auto mode) "Claude Haiku 4.5" are real, though — no OpenAI or Google key is configured, so manually picking "GPT-4o" or "Gemini 1.5 Pro" falls back to that agent's Claude default and surfaces a toast naming the substitution. True multi-provider support is the natural next step.
- **Auto-routing is a real heuristic, not a trained risk model** — it only sees the objective's text (keyword-matched) and how many departments/sources are in scope, not real transaction data or run history. Deterministic and explainable, but a first cut, not the sophisticated risk scoring `03-the-margin/cost-curve.md`'s Leader tier implies.
- **The policy gate's severity scoring is a real but simple mapping, not a trained score** — Low/Medium/High map to fixed numbers (25/60/90) compared against the policy's threshold; deterministic and explainable, same honesty as auto-routing above, not a claim of true risk assessment. And the gate has one real pause point (before Strategy/Writer), not the Killer tier's true two-gate (generate, then separately approve distribution) — there's no "send externally" action in the Command Center to gate a second time.
- **Shadow AI discovery is real but narrow — it only sees what this platform itself can see** — Agent Registry drift and real Orchestrate substitution telemetry are genuine, not invented, but that's inherently everything this scan can detect: it cannot discover a personal ChatGPT account, an unsanctioned browser extension, or any tool use that never touches this app. Real discovery of *those* needs actual endpoint/CASB integration — a real audit at a real design partner, which is a GTM/pilot activity (Horizon 1 in `06-the-pitch/roadmap.md`), not something a coding session can build in this repo.
- **Workflow History's run comparison is a real side-by-side juxtaposition, not a computed diff** — checking two runs and comparing shows both full deliverables laid out next to each other, real data both sides; it doesn't highlight or compute what specifically changed between them (no text-diff algorithm).
- **Audit trail Q&A is single-turn, and bounded to the 300 most recent log rows** — each question is answered fresh from the workspace's most recent entries, with no memory of prior questions in the conversation and no access to older history beyond that window. Real and grounded within that scope, just not a multi-turn chat over the complete, unbounded log.
- **Department drill-down covers three pages, not the whole app** — Audit Trail, Model Spend, and Shadow AI Audit have no clean per-department field to filter on today (a schema change, not just a frontend one), so they're unfiltered. And it's real filtering of real rows, not the kind of aggregated per-department analytics (spend by department, risk by department) the original backlog phrasing could also imply.
- **Plan tiers are real caps with no real billing** — Free/Pro/Enterprise genuinely change the enforced daily Orchestrate limit (20/100/500) via an admin-only RPC, but there's no Stripe integration, no invoice, no card on file, and no gate stopping an admin from "upgrading" for free. It's a real plan/cap relationship without real payment behind it.

Closing these is the rest of Horizon 2: true multi-provider support, the integrations catalog, and real billing/payment behind the plan tiers.
