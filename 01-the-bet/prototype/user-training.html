Everything below is real and live: real Supabase Postgres, real authentication, real Claude API calls, real policy enforcement. It is not a mockup, except where a section says otherwise. Video walkthroughs are planned for later; this page is the written and clickable version.

0. Before you start

Two workspaces exist wherever you open the app.

The public demo. What you see before signing in. Shared and read only. You can click through every page, but nothing that changes data will work: no running Orchestrate, no saving a policy, no deciding an approval.

Your own workspace. Created automatically the first time you sign in, private to you and anyone you invite into it. Everything else on this page describes your own workspace.

1. Signing in and finding your role

Magic link, no password, auto-created on first sign-in.
  1. Click the auth widget in the top bar of any page and enter your email.
  2. You will get a magic link. There is no password. Click it and you are in.
  3. The first time you sign in, a private workspace is created for you automatically, pre-loaded with a starting set of agents and policies.
RoleWhat you can do
AdminEverything Analyst and Compliance Owner can do, plus reassign agent models, manage the team, change the plan, and everything in Setting up your workspace below.
Compliance OwnerEdit policies, decide Shadow AI findings (govern or kill). Admins can do this too.
AnalystRun Orchestrate, approve or reject requests, run a Shadow AI scan, ask the audit trail a question.

Any control you cannot use for your role is disabled in the interface, and rejected on the server too, so this is not just cosmetic. If you belong to more than one workspace, a switcher appears near the auth widget.

On a phone. The navigation bar scrolls horizontally and automatically scrolls to the current tab. The Approval Queue also has a dedicated mobile companion view.

2. Setting up your workspaceAdmin only

Everything here lives in the Workspace modal, opened from the auth widget. Skip to Section 3 if you are not an Admin.

Invite your team. Workspace, then Team: enter a teammate's email, pick their role, and send it. They join automatically the next time they sign in with that email, with no accept step needed. Not yet available: a member leaving on their own, or changing their own role.

Set the plan and usage caps. Free, Pro, or Enterprise sets two real, enforced limits at once: Orchestrate runs per rolling 24 hours (20, 100, or 500) and real dollars spent per rolling 24 hours ($5, $25, or $150, at real Anthropic rates). Either limit alone can stop a new run. There is no real billing behind this yet; changing the plan only changes the enforced numbers.

Turn on Emergency Stop if needed. One real switch that freezes every new Orchestrate run, every paused run resume, and every external agent's approval check, for the whole workspace, until an Admin lifts it. Real for everything Aiven itself runs; it cannot reach into an external agent's own code if that code never checks in first.

Connect your own OpenAI or Google key. By default, "GPT-4o" and "Gemini 1.5 Pro" fall back to Claude without asking. Paste your own key into Workspace, then Provider Keys, and that provider becomes real: encrypted at rest, never shown again after saving. The Anthropic, OpenAI, and Google indicators in the top bar reflect this live; hover over one to see why.

Set up webhook notifications. Workspace, then Webhook Notifications, takes a plain POST URL (a Slack or Teams incoming webhook, or any generic endpoint). The moment a run pauses for approval, Aiven sends a real JSON message to it. Every attempt is logged and shown as "last delivery: succeeded or failed, and how long ago."

Set a data retention window. Workspace, then Data Retention, sets an automatic deletion window (30, 90, 180, or 365 days, or none, which is the default) for Audit Trail and Workflow History rows. Enforced daily, plus a "Run retention now" button for immediate, verified proof. This cannot be undone.

3. Running your first Orchestrate

The Command Center (index.html): the page you will use most.
  1. Enter a business objective, for example: "Assess our Q3 vendor risk exposure and recommend next steps."
  2. Pick departments and data sources in scope using the chips.
  3. Choose routing: leave Auto-route models by risk and complexity on (the default), or turn it off to assign each agent's model yourself.
  4. Click Orchestrate.

Six independent, real Claude API calls run in sequence: Research, Finance, Operations, Risk and Compliance, Strategy, Executive Writer. Each one reads the prior agents' real output. Watch the timeline light up as each step completes.

Two safeguards run automatically before your objective is sent anywhere. Redaction masks Social Security numbers, emails, phone numbers, credit card numbers, and API-key-shaped strings. Prompt injection screening neutralizes attempts to override or extract instructions, marked as [FLAGGED:PROMPT_INJECTION]. Both are logged to the Audit Trail and shown in an on-screen message.

If the run pauses, see Section 4. That is expected, not an error. When it finishes, you get an executive summary, findings, recommendations, and risk flags. Copy it as Markdown, print it, or find it later in Workflow History.

Running the same analysis often? Save the objective, scope, and routing as a named template and reload it later. Templates are shared across your whole workspace.

4. Policies and gates

policies.html: the Core tier is the one policy a real run actually checks.

A run only pauses because of the Core tier policy: an autonomy level, a risk threshold from 0 to 100, and a plain-language escalation rule.

  • Autonomous or Advisory. The flag is shown, but the run always continues. Nothing pauses.
  • Approval required. A flag at or above the threshold pauses the run before Strategy and Writer run (this is gate 1). A human has to decide.
  • Two-gate. Gate 1 works the same way, plus a real gate 2: every run this policy produces is held out of Workflow History until a second, separate approval releases it, whether or not gate 1 ever fired.

Only Admins and Compliance Owners can edit a policy, and every save is logged. When gate 1 pauses a run, decide it from the Command Center's own panel or from the org-wide Approval Queue (Section 5). Both have the same real effect.

5. Managing approvals

approvals.html: the org-wide backlog of everything waiting on a human.

Filterable by risk and department. Anyone in the workspace can approve or reject. Two kinds of rows behave differently:

  • A regular approval (a paused Orchestrate run, or an external agent): Approve resumes the run's remaining Claude calls, Reject ends it for good.
  • A release approval, titled Release: [objective]: this is gate 2 under Two-gate. The run already finished, so Approve releases it into Workflow History and Reject keeps it held back.

Raised by links straight back to the agent's Agent Registry row. On your phone, use the mobile companion view for the same live queue and the same real decisions, with large Approve and Reject cards.

6. Managing agents

agents.html: every agent the orchestrator governs.

Claude Sonnet 5 and Claude Opus 4.8 are always real routing targets. GPT-4o and Gemini 1.5 Pro become real once your workspace connects its own provider key. Otherwise they silently fall back to Claude and tell you so in a message. That mismatch is exactly what the Shadow AI Audit (Section 9) is built to catch.

Filter by tier or department. A Review status is clickable exactly when there is a real pending approval raised by that agent. The Pipeline column shows each Command Center agent's real step number, and an Admin-only Enabled checkbox genuinely removes an agent from the next real Orchestrate run.

Add an external agent to connect anything your team already runs elsewhere. You get a real API key and endpoint, shown exactly once. The honest limit: Aiven never runs that agent itself, so a gate only works if that agent's own code checks in first and honors the answer.

7. Auditing every action

audit.html: a real-time, searchable log of every agent and human action.

Approvals, policy saves, orchestrate runs: everything lands here immediately. Export the current view as JSON or CSV. Filter by department; actor and action entries link back to the Agent Registry or Approval Queue row they are about, whenever that resolves to something real.

Ask the audit trail. A plain-language question gets a real Claude answer, grounded strictly in your workspace's own most recent 300 log entries. If the log does not support an answer, it says so. This has its own separate limit from Orchestrate: 40 questions per rolling 24 hours.

8. Reporting

Three pages, three different jobs.

Workflow History (workflow-history.html): a real, searchable archive of every completed run's full deliverable. Each step has a "View prompt" option showing the exact prompt that agent's call received. A Two-gate run shows a "Pending release" badge until its release approval clears. Check any two rows and click "Compare selected" for a real side-by-side view.

Model Spend Dashboard (spend.html): two things kept separate. "Cost by tier and provider" is a modeled projection, illustrative, not billed. "Real Orchestrate spend" is every real Claude call your workspace has made, priced at real Anthropic rates, measured rather than modeled.

Governance Snapshot (governance-snapshot.html): a single-document bundle of your real policies, approval record, and audit trail, formatted for an actual auditor or customer security review. "Print, or save as PDF" strips the console frame for a genuine document. "Copy as Markdown" copies the same content as plain text.

9. Governing AI use: Shadow AI Audit

shadow-ai.html: three real checks against your own workspace's real data.
  1. Does an agent's assigned model fail to match a model this workspace can actually call? Real registry drift.
  2. Has a real run requested an ungoverned model and been silently substituted? A real, repeated request for something not really governed.
  3. Has a single call's token usage spiked sharply above that agent's own rolling average? A real, deterministic 3-sigma check, not trained machine learning, needing at least 5 prior calls before it trusts a baseline.

Every finding waits on an Admin or Compliance Owner to Govern it (log it, accept as known, nothing else changes) or Kill it (flag it as needing real action, such as fixing the registry or digging into the anomalous run; Kill does not automatically fix anything by itself). This cannot detect outside tool use, such as a personal ChatGPT account or an unsanctioned browser extension, since nothing about those ever touches this app.

10. Resetting demo data

Every page has a "Reset demo data" link in the footer. It only resets the shared public demo workspace. Your own signed-in workspace is never touched by it.
