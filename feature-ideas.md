# Feature Ideas Backlog

Running list of ideas surfaced while building the prototype that are out of scope for the current clickable demo. Nothing here is committed — triage into a module (or into a real build) when there's time.

## Product surface
- ~~Per-department drill-down analytics~~ — **built**: a real department filter, driven by each workspace's own real data (not a fixed list), on the three pages that actually carry a clean department field — Agent Registry (`agents.dept`), Approval Queue (`approvals.dept`), and Workflow History (`orchestrate_runs.departments`, since one run can span several). Agent Registry's "Departments covered" KPI tile is clickable and jumps straight to the filter. Not extended to Audit Trail, Model Spend, or Shadow AI Audit — none of those tables carry a real per-department field to filter on without a schema change.
- ~~Workflow history / versioned deliverable archive~~ — **built**: `01-the-bet/prototype/workflow-history.html` archives every completed Orchestrate run's full deliverable in real Postgres (`orchestrate_runs`, `01-the-bet/prototype/supabase/migrations/0013_workflow_history.sql`) — not just the Audit Trail's one-line pointer, and not just what's still in the browser tab that ran it. ~~Comparing two runs side-by-side is still open~~ — **built**: check up to two rows and click "Compare selected" for a real side-by-side view of both full deliverables (objective, scope, model, executive summary, findings, recommendations, risk flags, every agent step) — a plain-language juxtaposition of the two real archived runs, not a computed text diff.
- ~~Natural-language audit trail Q&A~~ — **built**: `01-the-bet/prototype/audit.html` has an "Ask the audit trail" panel — a real Claude call (`supabase/functions/audit-qa/`) grounded strictly in the workspace's real `audit_log` rows, instructed to say so plainly rather than invent an answer when the log doesn't support one. Real per-workspace rate limit (40 questions/day) and a real, persisted Q&A history (`audit_qa_log`, `01-the-bet/prototype/supabase/migrations/0014_audit_qa.sql`).
- Slack/Teams-native approval actions (approve/reject without opening the console)
- ~~Mobile companion view scoped to just the approval queue, for executives on the go~~ — **built**: `01-the-bet/prototype/mobile-approvals.html` is a real, phone-first page (not a responsive squeeze of the desktop table) — pending/high-risk KPIs, a Pending/All toggle, and card-based rows with big Approve/Reject tap targets, backed by a new lean read (`Aiven.getApprovalQueue()`, just the `approvals` table, not the full five-table `loadState()` payload) and the same `decideApproval()`/`resumeOrchestrate()` writes the full Approval Queue uses — deciding from a phone has the identical real effect (including resuming a paused Orchestrate run) as deciding from the desktop console. Linked from `approvals.html` ("Open the mobile companion view →") and back again; deliberately left out of the byte-identical 8-page subnav since it's a companion view, not a tenth console page.
- ~~Saved objective templates~~ — **built**: the Command Center can save the current objective, department/source scope, auto-route setting, and per-agent model picks as a named template (`objective_templates`, `01-the-bet/prototype/supabase/migrations/0015_objective_templates.sql`), and load one back in with one click — real, client-writable rows, open to any workspace member.

## Competitive differentiation — what the 2026 market actually rewards
Surfaced from researching current agent-governance platforms (Fiddler AI, Arthur AI, Portkey, Nango, Workato — see `06-the-pitch/backlog.md` for sourcing). None of these are built yet; flagged here as the honest next tier of "what would make this stand out," each noted with whether it's buildable today or needs something external.
- **Inline PII/secrets redaction on agent input and output** — the single most-cited governance feature across every competitor researched. Buildable now: a real pattern-matching pass (SSNs, emails, phone numbers, credit-card numbers, API-key-shaped strings) before and after each Claude call, masking matches and logging a real, auditable finding rather than blocking silently.
- **Prompt-injection screening on the objective input** — same shape as PII redaction, same PR. Buildable now: a real keyword/pattern heuristic flags an objective before it ever reaches an agent.
- **Full prompt/response visibility per step** — closes the "model version, approvals, diffs" audit-depth bar competitors are graded on. Buildable now: the exact system/user prompt each agent receives is already computed in `runOneAgent`, just not persisted or shown.
- **Workspace-wide emergency stop, distinct from per-agent disable** — the Agent Registry's new Enabled toggle (above) turns off one agent at a time; a real admin "pause every future Orchestrate run in this workspace immediately" switch is a different, higher-severity control most governance platforms treat as table stakes. Buildable now: one boolean on `workspaces`, checked first thing in the Edge Function.
- **Real dollar spend caps, not just a run-count cap** — today's cap is "N Orchestrate runs/day" regardless of what any one run actually costs; a workspace with unusually complex objectives could burn far more real budget than one with the same run count and simple ones. Buildable now: sum real `orchestrate_call_log` cost instead of counting `orchestrate_usage` rows.
- **Anomaly detection over real historical telemetry** — flag when an agent's real token usage or latency deviates sharply from its own rolling baseline (a real, deterministic statistical check, not ML) as a Shadow AI Audit-style finding. Buildable now: the raw telemetry (`orchestrate_call_log`) already exists; this is a new query and threshold, not new instrumentation.
- **Data residency / retention controls** — a real, workspace-configurable auto-delete window for `audit_log`/`orchestrate_runs` past N days. A common real enterprise procurement ask (GDPR data-minimization), not yet modeled anywhere in this schema. Buildable now: a scheduled Postgres job + a workspace-level setting.
- **Exportable governance snapshot** — a real, on-demand bundle (policies + approvals + a date range's audit trail, not just the Audit Trail's own JSON/CSV) formatted for an actual auditor or customer security review. Buildable now, mostly a new report view over data that already exists.
- **Workspace-configured webhook notifications** (e.g. "POST to this URL when a run pauses for approval") — closes the loop without a human having to actively watch the Approval Queue. Note this is genuinely buildable now without new credentials: a plain incoming-webhook URL (what Slack/Teams/generic HTTP all support) is just a URL an admin pastes in — no OAuth app registration needed, unlike the "Slack/Teams-native approval actions" item above, which does need one.
- **Bring-your-own provider key, per workspace** — reframes "true multi-provider support" from a platform-wide credential Aiven itself needs (OpenAI/Google keys covering every customer) into a per-workspace one: a customer supplies and stores their own OpenAI/Google key (encrypted), and multi-provider routing becomes real for exactly the customers who bring a key, with zero platform-wide credential exposure. Worth revisiting the "needs credentials" framing on multi-provider routing through this lens.
