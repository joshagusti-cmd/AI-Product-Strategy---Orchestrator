# Feature Ideas Backlog

Running list of ideas surfaced while building the prototype that are out of scope for the current clickable demo. Nothing here is committed — triage into a module (or into a real build) when there's time.

## Product surface
- ~~Per-department drill-down analytics~~ — **built**: a real department filter, driven by each workspace's own real data (not a fixed list), on the three pages that actually carry a clean department field — Agent Registry (`agents.dept`), Approval Queue (`approvals.dept`), and Workflow History (`orchestrate_runs.departments`, since one run can span several). Agent Registry's "Departments covered" KPI tile is clickable and jumps straight to the filter. Not extended to Audit Trail, Model Spend, or Shadow AI Audit — none of those tables carry a real per-department field to filter on without a schema change.
- ~~Workflow history / versioned deliverable archive~~ — **built**: `01-the-bet/prototype/workflow-history.html` archives every completed Orchestrate run's full deliverable in real Postgres (`orchestrate_runs`, `01-the-bet/prototype/supabase/migrations/0013_workflow_history.sql`) — not just the Audit Trail's one-line pointer, and not just what's still in the browser tab that ran it. ~~Comparing two runs side-by-side is still open~~ — **built**: check up to two rows and click "Compare selected" for a real side-by-side view of both full deliverables (objective, scope, model, executive summary, findings, recommendations, risk flags, every agent step) — a plain-language juxtaposition of the two real archived runs, not a computed text diff.
- ~~Natural-language audit trail Q&A~~ — **built**: `01-the-bet/prototype/audit.html` has an "Ask the audit trail" panel — a real Claude call (`supabase/functions/audit-qa/`) grounded strictly in the workspace's real `audit_log` rows, instructed to say so plainly rather than invent an answer when the log doesn't support one. Real per-workspace rate limit (40 questions/day) and a real, persisted Q&A history (`audit_qa_log`, `01-the-bet/prototype/supabase/migrations/0014_audit_qa.sql`).
- Slack/Teams-native approval actions (approve/reject without opening the console)
- ~~Mobile companion view scoped to just the approval queue, for executives on the go~~ — **built**: `01-the-bet/prototype/mobile-approvals.html` is a real, phone-first page (not a responsive squeeze of the desktop table) — pending/high-risk KPIs, a Pending/All toggle, and card-based rows with big Approve/Reject tap targets, backed by a new lean read (`Aiven.getApprovalQueue()`, just the `approvals` table, not the full five-table `loadState()` payload) and the same `decideApproval()`/`resumeOrchestrate()` writes the full Approval Queue uses — deciding from a phone has the identical real effect (including resuming a paused Orchestrate run) as deciding from the desktop console. Linked from `approvals.html` ("Open the mobile companion view →") and back again; deliberately left out of the byte-identical 8-page subnav since it's a companion view, not a tenth console page.
- ~~Saved objective templates~~ — **built**: the Command Center can save the current objective, department/source scope, auto-route setting, and per-agent model picks as a named template (`objective_templates`, `01-the-bet/prototype/supabase/migrations/0015_objective_templates.sql`), and load one back in with one click — real, client-writable rows, open to any workspace member.

## Governance & model management
- ~~Data-driven Agent Registry — real pipeline, not a hardcoded array~~ — **built**: the Command Center's real pipeline now reads its agents from the workspace's own `agents` table (`sequence_order`/`is_writer`/`is_risk_gate`/`enabled` columns, `01-the-bet/prototype/supabase/migrations/0016_data_driven_pipeline_agents.sql`) instead of a fixed six-entry array in the Edge Function — editing the registry genuinely changes what a real run does. Agent Registry's new **Pipeline** column shows each agent's real step number, Writer/Risk-gate tags, and a real Enabled toggle (Admin-only) that removes an agent from the very next real run without deleting it. Also fixed a real pre-existing gap this surfaced: the live pipeline's Risk & Compliance Agent had never actually had a registry row at all. Not yet built in this pass: reordering the pipeline or editing an agent's role/prompt text from the UI (both real, both held back for now as a deliberate scope cut — the Edge Function validates the pipeline's structural invariants either way, so a bad manual edit fails safely rather than silently).
- ~~Universal external-agent connector~~ — **built**: any agent a workspace already runs elsewhere (any stack, any language) gets a real API key + endpoint from Agent Registry's **+ Add external agent** flow (`agents.html`, `assets/data.js` `registerExternalAgent`), and reports its own real activity into the same registry, Audit Trail, and Approval Queue an internal agent uses via a new Edge Function (`functions/agent-events/`, `01-the-bet/prototype/supabase/migrations/0017_external_agent_connector.sql`). A reported `riskFlag` is judged by the exact same Core-tier policy the internal pipeline uses — crossing the threshold creates a real approval — and the external agent's own code can poll a real `check_approval` action before proceeding. Only a SHA-256 hash of the key is ever stored; the raw key is shown once at registration or regeneration. Honest limit, same as every real governance platform: Aiven can't force an external agent's code to call in or honor the answer, since it doesn't execute that agent itself.
- ~~Cost-based *automatic* model routing (cascade cheap→frontier model by task risk/complexity, referenced in `03-the-margin/cost-curve.md`)~~ — **built, partially**: the Command Center's "Auto-route models" toggle (on by default) hands model choice to a real, deterministic three-tier cascade in the Edge Function (`computeAutoRoute`) — risk keywords in the objective + department/source scope size decide baseline/elevated/high, escalating to Opus 4.8 only where warranted. Manual per-agent routing (the dropdowns) still works with the toggle off. Not yet built: a trained/scored risk model (this is keyword + scope heuristics, not real risk assessment) and true multi-provider routing.
- ~~Org-wide model spend dashboard broken out by agent, department, and provider~~ — **built at prototype fidelity**: `01-the-bet/prototype/spend.html`. ~~Real spend telemetry (vs. modeled cost-curve numbers) is still open.~~ — **built**: every real Orchestrate agent call now logs its real model and real token counts (`01-the-bet/prototype/supabase/migrations/0010_real_spend_telemetry.sql`), and the Model Spend Dashboard has a "Real Orchestrate spend" panel priced at real Anthropic per-model rates — measured $, not the modeled cost-curve numbers. The Leader/Filler/Killer tier breakdown stays modeled (it's the fraud/dispute vertical's economics, not something this prototype's real Orchestrate calls represent).
- ~~Policy editor — let a compliance owner define approval thresholds per risk tier instead of hardcoding them~~ — **built at prototype fidelity**: `01-the-bet/prototype/policies.html`. ~~Wiring it to actually gate a real agent's behavior is still open.~~ — **built**: the Core-tier policy (the tier every Command Center agent belongs to) now actually gates the real Orchestrate pipeline — set its Autonomy to "Approval-required" or "Two-gate" and a real run whose Risk & Compliance Agent flag crosses the threshold genuinely pauses before Strategy/Writer run, waiting on a real approval (Command Center panel or the org-wide Approval Queue) before those calls — and their real API cost — ever happen; rejecting it ends the run for real, no deliverable generated (`01-the-bet/prototype/supabase/migrations/0011_policy_gated_approvals.sql`, `supabase/functions/orchestrate/`).
- ~~Shadow AI discovery scan (tie-in to `05-the-guardrails/compounding-system.md`'s Shadow AI Audit)~~ — **built at prototype fidelity**: `01-the-bet/prototype/shadow-ai.html`. ~~Replacing the simulated scan with a real discovery audit is still open~~ — **built**: "Run Shadow AI Scan" now does a real, deterministic sweep of this workspace's own real data — Agent Registry entries whose declared model isn't one this platform can really call, and real Orchestrate runs that requested an ungoverned model and got silently substituted (`orchestrate_call_log.requested_model`, `01-the-bet/prototype/supabase/migrations/0012_shadow_ai_real_discovery.sql`) — instead of a fixed list of three fictional findings. Scoped narrowly and honestly: this still can't discover outside tool use (personal ChatGPT accounts, browser extensions) — that needs real endpoint/CASB integration, not just this workspace's own data, and stays part of the Horizon 1 "real Shadow AI Audit at a design partner" item in `06-the-pitch/roadmap.md`, which is a GTM/pilot activity, not something buildable in this repo.

## Competitive differentiation — what the 2026 market actually rewards
Surfaced from researching current agent-governance platforms (Fiddler AI, Arthur AI, Portkey, Nango, Workato — see `06-the-pitch/backlog.md` for sourcing). None of these are built yet; flagged here as the honest next tier of "what would make this stand out," each noted with whether it's buildable today or needs something external.
- ~~Inline PII/secrets redaction on agent input and output~~ — **built**: a real deterministic pattern-match pass (SSNs, emails, phone numbers, Luhn-validated credit-card numbers, API-key-shaped strings — `redactSensitive` in `supabase/functions/orchestrate/index.ts`) runs on the objective before it's ever prompted to an agent and on every agent's title/detail/summary/findings/recommendations/riskFlags text before it's stored or returned — matches are masked in place as `[REDACTED:TYPE]`, never silently dropped. Every masked value is counted, surfaced to the frontend the same way a model substitution already is (a real toast, and in the response body), and logged as a real `audit_log` entry. The universal external-agent connector (`functions/agent-events/index.ts`) runs the identical pass on every reported title/detail/riskFlag.text, since that's the one real input surface it has.
- ~~Prompt-injection screening on the objective input~~ — **built**: a real deterministic pattern-match pass (`screenPromptInjection` in `supabase/functions/orchestrate/index.ts`) checks the objective for override/extraction phrasing (imperative instruction overrides, system-prompt extraction attempts, chat-template injection markers, jailbreak framing) before it's ever redacted or prompted to an agent. A matched span is neutralized in place as `[FLAGGED:PROMPT_INJECTION]`, never silently dropped — every flag is counted, surfaced to the user via toast, carried through a pause/resume, and logged immediately as a real, high-severity `audit_log` entry (distinct from PII redaction's own logging, since injection screening only ever runs once, at intake).
- ~~Full prompt/response visibility per step~~ — **built**: each archived step in `runOneAgent` (`supabase/functions/orchestrate/index.ts`) now also carries the exact `promptSystem`/`promptUser` sent to Anthropic, captured at call time — no schema change needed since `orchestrate_runs.steps` was already jsonb, so it flows straight through both a fresh completion and a paused-run's `run_state`. `workflow-history.html` shows it behind a "View prompt" toggle per step. Runs archived before this shipped simply have no toggle — an honest gap, not a fabricated backfill.
- ~~Workspace-wide emergency stop, distinct from per-agent disable~~ — **built**: a real `emergency_stop` boolean on `workspaces` (`01-the-bet/prototype/supabase/migrations/0018_workspace_emergency_stop.sql`), flipped only by an admin-gated RPC (`set_emergency_stop`) surfaced in the Workspace modal (visible to every member, editable only by an admin). Checked first in both real Edge Functions: `orchestrate/index.ts` refuses a fresh run and a paused-run resume alike while it's active, and `agent-events/index.ts` forces any external agent's risk flag to gate regardless of the Core policy's threshold and answers every `check_approval` poll "not yet" — the higher-severity sibling of the per-agent Enabled toggle, real everywhere Aiven itself runs, same honest limit as the connector itself on code it doesn't execute.
- ~~Real dollar spend caps, not just a run-count cap~~ — **built**: a real `daily_spend_cap_usd` column on `workspaces` (`supabase/migrations/0019_real_dollar_spend_cap.sql`, tied to plan — Free $5/Pro $25/Enterprise $150 via the same `set_workspace_plan` RPC that already sets the run-count cap), checked by a new `checkSpendCap` in `orchestrate/index.ts` right alongside the existing run-count check — either one alone blocks a fresh run. Sums real cost from `orchestrate_call_log` over the same rolling-24h window, priced with the identical real Anthropic per-model rates `spend.html`'s "Real Orchestrate spend" panel already uses. Surfaced live in the Workspace modal's Plan section and a new "Today's spend / real cap" KPI on the Model Spend Dashboard.
- **Anomaly detection over real historical telemetry** — flag when an agent's real token usage or latency deviates sharply from its own rolling baseline (a real, deterministic statistical check, not ML) as a Shadow AI Audit-style finding. Buildable now: the raw telemetry (`orchestrate_call_log`) already exists; this is a new query and threshold, not new instrumentation.
- **Data residency / retention controls** — a real, workspace-configurable auto-delete window for `audit_log`/`orchestrate_runs` past N days. A common real enterprise procurement ask (GDPR data-minimization), not yet modeled anywhere in this schema. Buildable now: a scheduled Postgres job + a workspace-level setting.
- **Exportable governance snapshot** — a real, on-demand bundle (policies + approvals + a date range's audit trail, not just the Audit Trail's own JSON/CSV) formatted for an actual auditor or customer security review. Buildable now, mostly a new report view over data that already exists.
- ~~Workspace-configured webhook notifications~~ — **built**: an admin pastes a plain incoming-webhook URL into the Workspace modal (`webhook_endpoints`, `01-the-bet/prototype/supabase/migrations/0020_webhook_notifications.sql`) — no OAuth app, no new credential Aiven itself holds. `orchestrate/index.ts`'s new `fireWebhook` POSTs a real JSON payload (workspace name, objective, risk severity/text, approval id, timestamp) the moment a run actually pauses for approval — the one event nobody was otherwise notified of. Every real delivery attempt, success or failure, is logged to `webhook_deliveries` and shown in the Workspace modal as a real "last delivery" status line, not a leap of faith. Scope for this pass: only the `run.paused` event fires; no "send test webhook" button (a client-side test POST would hit CORS the pasted endpoint likely doesn't handle, unlike the server-side Deno fetch a real delivery uses) — a natural fast-follow.
- **Bring-your-own provider key, per workspace** — reframes "true multi-provider support" from a platform-wide credential Aiven itself needs (OpenAI/Google keys covering every customer) into a per-workspace one: a customer supplies and stores their own OpenAI/Google key (encrypted), and multi-provider routing becomes real for exactly the customers who bring a key, with zero platform-wide credential exposure. Worth revisiting the "needs credentials" framing on multi-provider routing through this lens.
