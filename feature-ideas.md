# Feature Ideas Backlog

Running list of ideas surfaced while building the prototype that are out of scope for the current clickable demo. Nothing here is committed — triage into a module (or into a real build) when there's time.

## Product surface
- ~~Per-department drill-down analytics~~ — **built**: a real department filter, driven by each workspace's own real data (not a fixed list), on the three pages that actually carry a clean department field — Agent Registry (`agents.dept`), Approval Queue (`approvals.dept`), and Workflow History (`orchestrate_runs.departments`, since one run can span several). Agent Registry's "Departments covered" KPI tile is clickable and jumps straight to the filter. Not extended to Audit Trail, Model Spend, or Shadow AI Audit — none of those tables carry a real per-department field to filter on without a schema change.
- ~~Workflow history / versioned deliverable archive~~ — **built**: `01-the-bet/prototype/workflow-history.html` archives every completed Orchestrate run's full deliverable in real Postgres (`orchestrate_runs`, `01-the-bet/prototype/supabase/migrations/0013_workflow_history.sql`) — not just the Audit Trail's one-line pointer, and not just what's still in the browser tab that ran it. Not yet built: comparing two runs side-by-side ("this quarter's plan vs. last quarter's") — today it's a real archive you can search and open one at a time, not a diff view.
- ~~Natural-language audit trail Q&A~~ — **built**: `01-the-bet/prototype/audit.html` has an "Ask the audit trail" panel — a real Claude call (`supabase/functions/audit-qa/`) grounded strictly in the workspace's real `audit_log` rows, instructed to say so plainly rather than invent an answer when the log doesn't support one. Real per-workspace rate limit (40 questions/day) and a real, persisted Q&A history (`audit_qa_log`, `01-the-bet/prototype/supabase/migrations/0014_audit_qa.sql`).
- Slack/Teams-native approval actions (approve/reject without opening the console)
- ~~Mobile companion view scoped to just the approval queue, for executives on the go~~ — **built**: `01-the-bet/prototype/mobile-approvals.html` is a real, phone-first page (not a responsive squeeze of the desktop table) — pending/high-risk KPIs, a Pending/All toggle, and card-based rows with big Approve/Reject tap targets, backed by a new lean read (`Aiven.getApprovalQueue()`, just the `approvals` table, not the full five-table `loadState()` payload) and the same `decideApproval()`/`resumeOrchestrate()` writes the full Approval Queue uses — deciding from a phone has the identical real effect (including resuming a paused Orchestrate run) as deciding from the desktop console. Linked from `approvals.html` ("Open the mobile companion view →") and back again; deliberately left out of the byte-identical 8-page subnav since it's a companion view, not a tenth console page.
- ~~Saved objective templates~~ — **built**: the Command Center can save the current objective, department/source scope, auto-route setting, and per-agent model picks as a named template (`objective_templates`, `01-the-bet/prototype/supabase/migrations/0015_objective_templates.sql`), and load one back in with one click — real, client-writable rows, open to any workspace member.

## Governance & model management
- ~~Cost-based *automatic* model routing (cascade cheap→frontier model by task risk/complexity, referenced in `03-the-margin/cost-curve.md`)~~ — **built, partially**: the Command Center's "Auto-route models" toggle (on by default) hands model choice to a real, deterministic three-tier cascade in the Edge Function (`computeAutoRoute`) — risk keywords in the objective + department/source scope size decide baseline/elevated/high, escalating to Opus 4.8 only where warranted. Manual per-agent routing (the dropdowns) still works with the toggle off. Not yet built: a trained/scored risk model (this is keyword + scope heuristics, not real risk assessment) and true multi-provider routing.
- ~~Org-wide model spend dashboard broken out by agent, department, and provider~~ — **built at prototype fidelity**: `01-the-bet/prototype/spend.html`. ~~Real spend telemetry (vs. modeled cost-curve numbers) is still open.~~ — **built**: every real Orchestrate agent call now logs its real model and real token counts (`01-the-bet/prototype/supabase/migrations/0010_real_spend_telemetry.sql`), and the Model Spend Dashboard has a "Real Orchestrate spend" panel priced at real Anthropic per-model rates — measured $, not the modeled cost-curve numbers. The Leader/Filler/Killer tier breakdown stays modeled (it's the fraud/dispute vertical's economics, not something this prototype's real Orchestrate calls represent).
- ~~Policy editor — let a compliance owner define approval thresholds per risk tier instead of hardcoding them~~ — **built at prototype fidelity**: `01-the-bet/prototype/policies.html`. ~~Wiring it to actually gate a real agent's behavior is still open.~~ — **built**: the Core-tier policy (the tier every Command Center agent belongs to) now actually gates the real Orchestrate pipeline — set its Autonomy to "Approval-required" or "Two-gate" and a real run whose Risk & Compliance Agent flag crosses the threshold genuinely pauses before Strategy/Writer run, waiting on a real approval (Command Center panel or the org-wide Approval Queue) before those calls — and their real API cost — ever happen; rejecting it ends the run for real, no deliverable generated (`01-the-bet/prototype/supabase/migrations/0011_policy_gated_approvals.sql`, `supabase/functions/orchestrate/`).
- ~~Shadow AI discovery scan (tie-in to `05-the-guardrails/compounding-system.md`'s Shadow AI Audit)~~ — **built at prototype fidelity**: `01-the-bet/prototype/shadow-ai.html`. ~~Replacing the simulated scan with a real discovery audit is still open~~ — **built**: "Run Shadow AI Scan" now does a real, deterministic sweep of this workspace's own real data — Agent Registry entries whose declared model isn't one this platform can really call, and real Orchestrate runs that requested an ungoverned model and got silently substituted (`orchestrate_call_log.requested_model`, `01-the-bet/prototype/supabase/migrations/0012_shadow_ai_real_discovery.sql`) — instead of a fixed list of three fictional findings. Scoped narrowly and honestly: this still can't discover outside tool use (personal ChatGPT accounts, browser extensions) — that needs real endpoint/CASB integration, not just this workspace's own data, and stays part of the Horizon 1 "real Shadow AI Audit at a design partner" item in `06-the-pitch/roadmap.md`, which is a GTM/pilot activity, not something buildable in this repo.

## Platform / real build
- ~~Replace simulated agent runs with real API calls to Claude, GPT, and Gemini behind a common orchestration interface~~ — **built, partially**: the Command Center's orchestration run is six real, independent Claude calls via a Supabase Edge Function (`01-the-bet/prototype/supabase/functions/orchestrate/`), one per agent, each seeing the prior agents' actual output — not one call inventing all six steps. The Command Center's per-agent model dropdown now drives real per-call routing (reassigning an agent's model really changes which model runs it), but not yet multi-provider — only Claude is real; picking "GPT-4o" or "Gemini 1.5 Pro" falls back to that agent's Claude default with a toast naming the substitution. See `01-the-bet/prototype.md`.
- ~~Real auth + multi-tenant workspace model (SSO/RBAC)~~ — **built, partially**: email magic-link sign-in with a real per-user private workspace, auto-provisioned and RLS-isolated, plus a read-only public demo for anonymous visitors (`01-the-bet/prototype/supabase/migrations/0003`–`0005`). A workspace member can now invite a teammate by email with a chosen role — they join automatically on their next sign-in, and a user in multiple workspaces gets a switcher (`0007_teams_and_invites.sql`). RBAC within a workspace is real too: three roles (Admin, Compliance Owner, Analyst) enforced by RLS, not just labeled (`0008_rbac_within_workspace.sql`). Not yet built: SSO, and any role/permission beyond those three fixed bundles. See `01-the-bet/prototype/supabase/README.md`.
- ~~Persistent backend~~ — **built**: a real Supabase Postgres database (`01-the-bet/prototype/supabase/migrations/`) replaces the localStorage simulation. State is now shared across every visitor, not just carried across pages in one browser.
- ~~Per-workspace spend caps / rate limiting on real Claude calls~~ — **built**: every workspace gets a rolling-24h Orchestrate cap, enforced server-side in the Edge Function via the service role key (`01-the-bet/prototype/supabase/migrations/0006_orchestrate_rate_limit.sql`). Now tied to a real plan tier too — Free/Pro/Enterprise → 20/100/500, changeable by an admin via the Workspace modal (`0009_plan_tiers.sql`). Not yet built: real billing/payment behind the plan (no Stripe, no invoice — "upgrading" just changes the enforced number).
- Integrations catalog for the data sources currently just listed as chips (NetSuite, Salesforce, Zendesk, Snowflake, Workday)
